## 1. 立项起点：我们要解决什么

### 1.1 项目缘起

2026 年 7 月立项时，对外材料是散的：一份 PDF 作品集、几段经历写在简历里、社交账号各自为政。招聘方、合作方或同学点开一个链接时，核心问题不是「她会哪些软件」，而是：

**这个人现在做什么、做过什么、作品在哪、怎么联系——能不能在一次访问里看完，而不必下载文件、切换语言、或被一份学生作品集盖过当前的职业叙事？**

市面个人站往往把「最新文章」或「全部项目卡片」当主角。本项目从立项第一天起，把主角定为：**一个可转发的身份页**。首页讲现在的职业位置，作品集是可翻的证据，兴趣说明人，联系把转化做完。

### 1.2 问题定义（Problem Statement）

| ID | 问题 | 用户表现 | 若不解决的后果 |
| --- | --- | --- | --- |
| P1 | 身份说不清 | 打开首页不知道她是设计师、前端还是驻场交付 | 30 秒内离开，或按错误岗位理解 |
| P2 | 证据太重或太轻 | PDF 作品集要下载；经历若全堆在首页又淹没首屏 | 要么不看，要么看完记不住当前工作 |
| P3 | 中英观众不是同一批人 | 国内招聘看中文，海外或英文材料需要另一套说法 | 一份文案两头不讨好 |
| P4 | 内容更新靠改代码 | 改一句经历、换一部人生电影都要发版 | 站会过时，本人不愿维护 |
| P5 | 联系动作分散 | 邮箱、微信、小红书、作品二维码不在同一处 | 有意向也找不到下一步 |

### 1.3 目标用户

**主用户：** 看完一页就要决定是否继续聊的人——招聘方、业务合作方、想约项目的人。桌面端细读，手机端转发后快速扫。

**次用户：** 本人。需要改经历、电影、作品条目和联系信息，但不把站点做成公开后台。

**非用户：** 不服务博客读者，不做作品评论区，不服务需要登录才能看内容的访客。

### 1.4 产品目标与成功标准

| 目标 | 可验收成功标准 |
| --- | --- |
| 身份 30 秒可读 | 首页首屏同时给出头衔、姓名、教育、一句 tagline、两条行动 |
| 现在与过去分层 | 首页只展示两条当前工作；完整路径在「经历」 |
| 作品可在站内看完 | 四个设计项目可从封面跳到对应页；翻页不离开站点、不下载 PDF |
| 中英平行可用 | 同一栏目在 `/` 与 `/en` 各有一版；切换后仍停在对应页面 |
| 联系可完成 | 邮箱、社交、微信、二维码在联系页一次列清 |
| 中文内容可维护 | 登录后台可改档案、经历、技能跑马灯、作品元数据、电影，无需改前端文案文件 |

### 1.5 非目标（立项即写死，迭代中保持）

- 不做博客、RSS、评论、点赞。
- 不做访客账号；后台只给站点主人。
- 不做中英机器互译。英文是另一份写好的文案，不是中文的运行时翻译。
- 不把简历内页放进对外作品集翻页（作品集服务「设计项目」，不服务「投递简历」）。
- 不做作品在线批注、外链 Figma 作为主路径。主路径是站内翻页。
- 兴趣卡片默认不可点进详情。只有「观影」进入电影页，避免十二个空子页。

## 2. 产品原则（从起点钉死）

| 原则 | 含义 | 对设计的约束 |
| --- | --- | --- |
| 首页讲现在 | 当前职业身份优先于作品集全集 | 作品在首页只做预告，不占首屏 |
| 一页一事 | 经历、作品、兴趣、联系职责不重叠 | 禁止把时间线、翻页器、兴趣墙堆进同一屏当目录 |
| 证据可点到 | 每个对外主张旁边要有去处 | 「完整经历」「浏览作品集」「来聊聊」必须落到真实页面 |
| 中英是两扇门 | 语言切换是换站点，不是换字典 | 导航、标题、经历、项目名、电影主标题分别维护 |
| 公开页可离线读懂 | CMS 挂了也不能白屏 | 中文读取失败时回退到仓库内静态数据 |
| 本人可改、访客不可进 | 内容运营和作品展示分开 | `/admin` 需登录；公开页无编辑入口 |
| 小标题先定调 | 每个板块用英文眉标 + 中文大标题 | 眉标负责节奏（Experience、Path、Works），大标题负责说人话 |

视觉：浅底内容面 + 深色强调带交替，强调色用于行动和当前项。深色模式由访客本地记住，不跟账号走。字体中文用 Noto Sans SC，西文用 Inter。

## 4. 信息架构与关键用户路径

### 4.1 信息架构

| 层级 | 模块 | 路径 | 职责 |
| --- | --- | --- | --- |
| 导航 | 首页 | `/` 、`/en` | 身份、当前工作摘要、能力、作品预告 |
| 导航 | 经历 | `/about` 、`/en/about` | 完整时间线 + 技能地图 |
| 导航 | 作品 | `/projects` 、`/en/projects` | 项目索引 + 站内翻页 |
| 导航 | 兴趣 | `/interests` 、`/en/interests` | 五组生活侧面 |
| 子页 | 电影 | `/interests/cinema` 、`/en/interests/cinema` | 人生电影。不单独占导航 |
| 导航 | 联系 | `/contact` 、`/en/contact` | 全部对外渠道 |
| 全站 | 顶栏 / 页脚 | 每页 | 定位、换语言、换主题、再进一次联系 |
| 后台 | 内容管理 | `/admin` | 仅主人。不出现在公开导航 |

### 4.2 顶栏规则

| 元素 | 规则 |
| --- | --- |
| 品牌 | 中文站「王悦」，英文站「Dewy」，回当前语言首页 |
| 主导航 | 首页、经历、作品、兴趣、联系。当前页加粗。电影页仍高亮「兴趣」 |
| 联系我 | 桌面端胶囊，直达联系页。窄屏收进菜单，避免和语言、主题抢位置 |
| 中 / EN | 切到同一内容的另一语言。电影留在电影，不退回兴趣列表。已是当前语言时点击无效。尽量保持滚动位置 |
| 主题 | 浅色 / 深色，写入本地，刷新后保持 |
| 手机菜单 | 重复主导航，并再提供中文 / English |

### 4.3 核心路径（验收用）

1. **认人：** 打开首页 → 读到 FDE 头衔、姓名、学校、一句主张 → 知道这是交付向的设计工程，不是纯作品集站。
2. **看现在：** 首页「走过的路」只看到两条在职经历 → 点「完整经历」到时间线。
3. **看作品：** 首页作品预告或导航「作品」→ 点项目封面 → 翻页器打开该项目第一页 → 方向键或缩略图翻完。
4. **换语言：** 在任意公开页点 EN → 落到英文同页，导航变为 Home / Path / Work / Interests / Contact。
5. **联系：** 顶栏或页脚「来聊聊」→ 邮件、社交、微信、二维码都在，邮箱可一键唤起邮件。
6. **改中文事实：** 主人登录后台 → 改经历或电影 → 中文公开页读到新内容；CMS 不可用时页面仍用仓库静态数据。

## 5. 内容模型（产品规格）

公开页不区分「文章类型」。内容分两类：**可运营的事实**（中文 CMS）和 **写死的结构与英文**（代码）。

### 5.1 中文可由后台改的实体

| 实体 | 关键字段 | 产品含义 |
| --- | --- | --- |
| 档案 Profile | 姓名、头衔、tagline、简介、邮箱、电话、城市、头像、社交、关于段落 | 首页与联系页的「这个人」 |
| 经历 Timeline | 类别、年份、标题、机构、描述、排序 | 首页摘两条工作；经历页全量分组 |
| 技能 Skill | 名称、熟练度、排序 | 首页深色跑马灯。熟练度当前不在公开页画成进度条 |
| 作品 Project | 编号、标题、类别、摘要、封面、起止页、是否可见、排序 | 作品索引与翻页器跳转。页图本身仍是静态文件 |
| 电影 Movie | 排名、中英名、年份、海报、IMDb、是否可见 | 人生电影列表 |
| 观影文案 | intro、habit | 电影页两段介绍。允许保存为空，不得用旧文案把空值填回去 |

### 5.2 不进后台的内容（本期）

| 内容 | 原因 |
| --- | --- |
| 英文全站文案 | 避免半套翻译；改英文等于改一版产品说法 |
| 兴趣分组与卡片 | 结构是设计过的五组叙事，不是流水账数据 |
| 能力三列（FDE / 设计系统 / AI Native） | 对外主张，改动应走产品而不是随手改库 |
| 联系页的渠道说明、开放状态 | 转化文案，和档案里的链接分开 |
| 作品集页图 | 来自《王悦-作品集 2026》导出的图片，换图是发版 |

### 5.3 经历如何被使用

类别固定为五组，顺序固定：工作经历、教育经历、实习经历、项目经历、工作坊 / 学术。

| 规则 | 说明 |
| --- | --- |
| 首页摘录 | 只取「工作经历」前两条。没有工作经历时才退回时间线前两条 |
| 教育胶囊 | 首页用教育条目生成一行学校 · 学历 · 年份，不重复展开课程 |
| 经历页教育卡 | 标题用学校，副标题用学历。其他类别标题用职位或项目，副标题用机构 |
| 空组不渲染 | 某一类没有条目时，整组标题不出现 |

### 5.4 作品与页码

源 PDF 31 页。对外翻页器去掉简历页（源文件第 3 页），访客看到的是连续的 30 页，页码按可见顺序显示，而不是按被删掉的源页号。

| 编号 | 中文项目 | 英文项目名 | 源页范围 |
| --- | --- | --- | --- |
| 01 | 从未来到未来 | From Future to Future | 5–10 |
| 02 | 保温杯结构设计 | Thermos structure design | 11–16 |
| 03 | 充电桩形态设计 | EV charger form design | 17–19 |
| 04 | Future Smart Home | Future Smart Home | 20–30 |

点项目 = 跳到 `startPage`，不是新开详情页。当前页落在某项目起止页之间时，对应标签高亮，说明文案为「编号 · 标题」。

## 6. 功能需求规格

### 6.1 首页

| ID | 需求 | 验收要点 |
| --- | --- | --- |
| F-HOME-1 | 眉标展示当前头衔，默认「FDE · AI Native 设计工程」 | 首屏第一眼是职业位置，不是姓名装饰 |

| F-I18N-1 | 中文根路径，英文 `/en` 前缀 | hreflang、canonical 成对 |

| F-THEME-1 | 首访可读；手动切换后本地记住 | 深色不是简单反色 |
| F-404 | 未知路径有站内 404，仍带顶栏页脚 | 不把访客扔出站点 |

### 6.7 后台（主人）

| ID | 需求 | 验收要点 |
| --- | --- | --- |

## 8. 上线逻辑复盘（2026-09-23）

对本轮已上线主路径做一致性检查，结论如下。

### 8.1 已理顺（保持）

| 链路 | 结论 |
| --- | --- |
| 首页身份 → 两条工作 → 经历全文 | 现在与过去分层清楚 |
| 作品预告 → 项目卡 → 翻页器页码 | 站内看完，简历页已排除 |
| 中 / EN → 同页另一语言，含子页电影 | 两套文案，不是插件翻译 |
| 兴趣五组 → 仅观影进入电影 → IMDb | 子页克制，海报可核验 |
| 顶栏 / 页脚 / 联系页 | 转化入口重复但职责一致：进联系，不在页脚再讲一遍经历 |
| 中文 CMS → 公开页；失败 → 静态数据 | 展示不依赖后台在线 |
| 深色模式本地记忆；语言切换记滚动 | 偏好不打扰内容 |

### 8.2 已知产品边界

| 边界 | 影响 | 当期策略 |
| --- | --- | --- |
| 英文不进 CMS | 改英文仍要发版 | 接受。英文是对外口径，不跟中文表单绑死 |
| 能力三列、兴趣、联系说明在代码里 | 后台改不了这些板块的措辞 | 接受。它们是结构设计，不是流水数据 |
| 作品页图静态 | 换一页画面要替换图片并发版 | 接受。后台只改标题、封面、起止页 |
| 技能熟练度已存储但不展示 | 后台的 level 访客看不见 | 跑马灯只承担「会什么」的节奏，不打分 |
| 电话在档案里，联系页不展示 | 公开转化不走手机号 | 保持。需要时由微信和邮箱承接 |
| 兴趣除观影外不可点 | 不能为每个爱好做专题 | 接受。空专题比一张写清楚的卡片更差 |
| 删除 / 隐藏无公开回收站 | 主人误藏项目会从站上消失 | 接受。数据仍在库里，重新勾选可见即可 |

### 8.3 残余说明

首页不自动滚到作品集。早期曾这样做，它会抢走「先认人」的第一屏，已取消。

作品集可见页序与源 PDF 页号不必一致。产品承诺的是「四个项目按顺序读完」，不是「和 PDF 页码对齐」。

复盘结论：主路径（认人、看经历、站内看作品、中英切换、完成联系、中文可改）逻辑一致，可对外演示与验收。上表取舍是明确边界，不在本期补成「什么都能在后台改」。

## 11. 最终产品介绍

这一节给打开仓库或作品集的人：不谈迭代过程，只讲现在这个产品是什么、怎么用、每一块在说什么。

### 11.1 一句话

王悦（Dewy）的个人主页，是一个中英双语的身份站。它用一页说清「Forward Deployed Engineer，设计和工程一起交付」，用经历页放下完整路径，用站内翻页器放下设计作品集，用兴趣和电影说明人，用联系页把下一步做完。

线上：https://wangyue-dewy.vercel.app  
英文从 https://wangyue-dewy.vercel.app/en 进入，或在顶栏点 EN。

### 11.2 适合谁、在什么时候打开

适合把链接丢进简历、邮件签名、社交简介，或当面把手机递过去。对方不需要装应用，也不需要下载 PDF。中文读者看根路径，英文读者看 `/en`。两套导航用词不同，但地图相同。

### 11.3 打开之后的 30 秒

顶栏先固定住：名字回首页，五个栏目，一颗「联系我」，语言和深色开关。

首屏左侧是眉标 **FDE · AI Native 设计工程**，大标题 **你好，我是王悦。** 下面一枚教育胶囊（中南大学本科，2027 应届），然后是一句主张：既关心体验是否说得通，也关心能不能稳定交付。两个按钮分别去「走过的路」和「联系我」。右侧是圆形头像。

到这里，访客应该已经知道：这不是一个作品集封面站，当前身份是驻场交付。

### 11.4 首页其余板块

**Experience · 走过的路。**  
三段自述：现在的 FDE 与教育科技业务；此前的小红书方言、字节即梦 Prompt Engineering、广汽概念车和《书斋与人间》；工作之外的潜水、攀岩、街舞、吉他、电影和咖啡。下面只放两张当前工作卡——咨询公司的 Forward Deployed Engineer，以及教育科技公司的交互设计与前端。要看实习、项目和工作坊，走「完整经历」。

**Capabilities · 能做什么。**  
三列，不打分：

- FDE 交付：驻场拆需求、设计到上线、Soft Ops、H5 / 小程序、CloudBase
- 设计系统与品牌：多品牌、Figma、IP 与物料、转化链路、审美评测
- AI Native 工作流：Cursor Agent Skills、验收标准、可复用 Prompt、工作日志

技能名在一条深色跑马灯里循环，用来增加节奏，不承担评分。

**Portfolio · 设计作品集。**  
一张可点的预告卡，四张封面横排，右上角「浏览作品集」。工业设计与概念项目在这里被承认，但不抢首页的主叙事。

页脚每一页都在。深色底上是「来聊聊吧」，然后分列导航、社交和联系信息，底部两行口号 Just do it / Just Dewy。

### 11.5 五个公开栏目

**经历。** 眉标 Path。标题是「走过的路，和还能做什么。」时间线按工作、教育、实习、项目、工作坊分组。教育卡把学校放在前面。页底再用「技能地图」重复那三列能力，让这一页可以单独转发。

**作品。** 四个项目：

1. 从未来到未来 — 广汽概念载具 HYPTEC TIDAL  
2. 保温杯结构设计

4. Future Smart Home — 中南大学 × 千叶大学工作坊  

点封面不会离开页面。下方翻页器有项目标签、16:9 画面、页码、上一页下一页和缩略图。键盘左右键可以翻。简历那一页故意不在里面。

**兴趣。** 十二件事，五组：动起来（潜水、街舞、攀岩、旅行）、开一局（桌游、国际象棋、台球）、好好笑（即兴喜剧、播客）、常思考（观影、阅读）、去感受（木吉他、咖啡）。组与组之间底色交替。页底邀请有同样爱好的人去联系。

**联系。** 「有想法？一起做点什么。」写明通常一到两个工作日回复，目前开放远程兼职与咨询。卡片覆盖邮箱 iKevinAyuso@163.com、GitHub Dewyue、小红书、抖音、Instagram @dewy_justdoit、LinkedIn、微信 Dewyue，以及可下载的主页二维码。落款是人在上海。

### 11.6 英文站在说同一件事的另一种说法

英文不是中文的逐句替换。品牌变成 Dewy，导航变成 Home、Path、Work、Interests、Contact。经历大标题是 The path so far。兴趣大标题是 Get moving、Play a round、Have a laugh、Think it through、Take it in。电影卡把英文片名放在主标题。项目名使用 From Future to Future、Thermos structure design、EV charger form design。结构、页序和六部电影不变。

### 11.7 主人怎么改，访客为什么无感

中文的姓名与简介、经历、跑马灯技能、作品标题与页范围、电影列表，可以在登录后的后台修改，数据放在 Turso，本地开发可以用 SQLite。公开页面没有编辑按钮。英文文案、兴趣分组和三列能力仍在代码里，因为它们是产品口径，不是一条条可随手改的记录。若后台暂时不可用，中文站退回仓库里的静态内容，访客仍能读完。

### 11.8 这个产品故意不做什么

它不写博客，不让人注册，不把十二个兴趣都做成专题，不在作品集里夹简历，也不承诺后台能改每一个英文句子。范围停在这里，是为了让一次访问始终完成四件事：知道你是谁，看到证据，感觉到人，找到你。
